## 5. Hardening Notes & Positive Source Patterns

### Non-Finding Hardening Notes
1. **Mobile offline-PIN password recovery at the 3-device cap (`mobile/digitva-collect/src/auth.ts:1322-1337`, `src/nativeRoutes/sign-in.tsx:89-90`)**: `verifyPassword` verifies the user's password by calling `POST /api/v1/auth/sessions` without `replace_device_id` and immediately revoking the session. If a user is signed out on the current phone (so `device_id` has no live row) while holding 3 active sessions on other phones, `POST /api/v1/auth/sessions` returns `409 device_limit` and blocks offline-vault PIN recovery unless another device signs out.
2. **iOS SmartVA worker lifecycle (`mobile/digitva-collect/modules/digitva-smartva/ios/DigitvaSmartvaModule.swift:14, 115`)**: `private let queue = SmartvaWorker()` is an instance property whose permanent background thread captures `[unowned self]`. Make `queue` `private static let` (matching `DigitvaIcd11Module.swift:17`) or capture `self` strongly so module deallocation during reload cannot trigger an unowned reference trap.
3. **Docker Compose `doris_public_service` environment/network isolation (`docker-compose.yml:154-172` vs `docker-compose.demo.yml:226-263`)**: In `docker-compose.demo.yml`, `demo_doris_public_service` runs on an isolated `demo_doris_public_net` with `DATABASE_URL: "sqlite:///:memory:"` and a dedicated `SECRET_KEY`. In `docker-compose.yml`, `doris_public_service` still inherits `<<: *common-variables` (sharing the main app secrets and PostgreSQL `DATABASE_URL`) and the default compose network; align `docker-compose.yml` with `docker-compose.demo.yml`.
4. **SmartVA parity script path containment (`scripts/smartva-parity/rescore_server.py:85-87`, `scripts/smartva-parity/compare.py:91-92`)**: Replace `if "private" not in out.parts` with `out.resolve().is_relative_to((REPO / "private").resolve())` so relative path traversal or external `/tmp/private/...` paths cannot bypass the check.
5. **Ingress `X-Forwarded-For` normalization (`deploy/ingress-common.conf:45-53`)**: Where nginx is deployed without a trusted upstream proxy normalizing `X-Forwarded-For`, configure `set_real_ip_from` / `real_ip_header X-Forwarded-For` (matching `deploy/ingress-demo.conf:13-22`) so rate-limit keys in `app/utils/rate_limit.py:16-24` cannot be spoofed via client headers.
6. **Legacy `/vaform/attachment/*` and `/vaform/media/*` training scope checks (`app/routes/va_form.py:1188-1229`)**: Add `training_scope.resolve('coding', 'review', 'interview')` and `training_scope.sid_allowed(record.va_sid)` to the legacy attachment routes to match `/api/v1/attachments/<storage_name_raw>` (`app/routes/api/attachments.py:29-48`).
7. **Training graduation security event logging (`app/services/training_demo_service.py:2205-2206`)**: Emit `record_security_event(..., event_type='coding_languages_changed')` when `graduate()` updates `user.vacode_language`, matching `import_trainees` (`line 1943`) and `PATCH /api/v1/profile/languages` (`app/routes/api/profile.py:254`).

### Positive Source Patterns Observed
- **Transactional 3-Device Slot Locking & Atomic Rollback (`app/services/device_auth_service.py:726-789`, `app/routes/api/auth.py:102-106`)**: `check_device_slot` locks the target `VaUsers` row `FOR UPDATE`, binds `replace_device_id` strictly to `AuthDeviceSession.user_id == user.user_id`, and runs before QR token consumption or demo cap failure so `409 device_limit` rolls back cleanly without consuming one-time tokens.
- **Consultation Guard & Grant Version Cache Invalidation (`app/services/authz/consulted.py`, `app/services/authz/grant_cache.py`)**: Every non-public, non-self-service endpoint is checked by `install_consultation_guard`, and grant mutations invalidate cached authorization state and emit rollback-safe notifications.
- **Native Engine Process Isolation & PII Stripping (`mobile/digitva-collect/src/workspace/piiBoundary.ts`, `Icd11Service.kt`, `SmartvaService.kt`, `shim.c`)**: Android runs native ICD-11 and SmartVA engines in separate `:icd11` and `:smartva` OS processes with bounded Binder reply budgets (`MAX_REPLY_UTF8_BYTES = 128 * 1024`), request caps, and client-side PII stripping (`assertNoPii`).
- **XLSX Zip-Bomb and Formula-Injection Defenses (`app/services/tabular_import_service.py`, `app/services/training_report_service.py:42-48`)**: Upload parsing enforces archive entry and uncompressed byte caps before `openpyxl.load_workbook(read_only=True)`, and CSV exports neutralize spreadsheet formula prefixes (`=`, `+`, `-`, `@`, `\t`, `\r`).
