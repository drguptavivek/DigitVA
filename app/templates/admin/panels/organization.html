Organization
How to set up an organization
Pick an organization-mode project above (set Structure: Organization in the Projects panel), then work through the tabs in order:
  1. Levels: define the tiers, top first (e.g. District > CHC > PHC > Village). Seed template adds a standard set.
  2. Units: add the actual places at each level, top level first, each under its parent. A facility list with no parents can be imported first (Export / Import), then placed with Map parents or by dragging.
  3. Cadres & permissions: the worker types, and at which level each may fill or code VA forms.
  4. Workers: attach health workers to units.
Optional: ODK form fields for projects that also collect through ODK; Export / Import to copy a tree.

Coding gate

Narrows coding for this unit's whole subtree unless a descendant sets its own gate. Never opens coding the project-site gate has closed — the stricter of the two always wins. No gate here means this unit simply inherits its nearest gated ancestor, if any.

{# ---- Levels ---- #}
Depth orders the tree (1 = top). Optional levels may be skipped when placing a unit.
{# Project coding scope — docs/policy/organization-model.md, "Coding scope" #}
Coding scope
A coder only ever codes deaths from the unit they are granted and the units beneath it; the pool never crosses that boundary. The scope level says within which level coding happens, and what people granted above it may do. Needs Pick and choose coding intake.

The kinds of health worker in this project. Then say at which levels each exists in Permissions by level.

{# ---- Export / Import ---- #}
Export

Master data as one workbook (levels, units, cadres, level_cadres, workers) or one CSV per sheet. The ODK choices CSV feeds the cascading unit selects of the XLSForm.

Workbook (.xlsx) ODK choices (.csv)
Import

Upload a workbook in the export layout, or a CSV of one sheet for quick adding. Rows are matched by code; nothing is deleted. Run the dry run first, then apply.

CSV templates (current data, edit and re-upload): cadres · level_cadres · units · workers

Import cadres before level_cadres, and both before workers: a worker's cadre must exist at its unit's level.
