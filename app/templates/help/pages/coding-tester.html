What Is the Coding Tester Role?

The coding_tester role is a specialized coder variant designed for testing and verifying the coding workflow on a small set of forms. It uses the same coding interface as a regular coder but is intended for quality assurance and workflow validation rather than production coding throughput.

How Coding Tester Differs from Regular Coder

Aspect Coder Coding Tester
Purpose Production coding Testing and verification of coding workflow
Coding interface Full coding interface Same full coding interface
Coding gates enforced Yes — all project gates must pass Bypasses most coding gates
Scope Project, project_site, or org_unit Project, project_site, or org_unit
Workflow state machine Standard coder track Standard coder track (bypasses site/unit date & daily limit gates)

What Happens to a Coding Tester's Codes?

When a user with the coding_tester role codes a form:

  • Gate bypass for pre-launch or off-window verification: A coding_tester can open and code forms even when a site or unit has coding_enabled = false, outside coding_start_date / coding_end_date, or when the daily_coder_limit has been reached.
  • In Demo / Training projects: Coding artifacts are temporary and automatically cleaned up after the project's retention window (demo_retention_minutes), returning the submission to its pre-demo state so multiple trainees or testers can practice on the same forms.
  • In Production projects: A coding_tester uses the standard coding state machine to verify end-to-end form rendering, ICD-10/ICD-11 lookup, NQA, and Social Autopsy before opening the gates to regular coders.

Coding Gate Bypass

A regular coder must satisfy all non-demo coding gates before entering the coding workflow:

  • coding_enabled = true
  • Current date is on or after coding_start_date (when set)
  • Current date is on or before coding_end_date (when set)
  • Per-site daily_coder_limit is not exceeded

A coding_tester may enter non-demo coding even when:

  • coding_enabled = false
  • The current UTC date is before coding_start_date
  • The current UTC date is after coding_end_date
  • The per-site daily_coder_limit has been reached
All coding gate checks use UTC date regardless of user timezone.

Scope and Access

The coding_tester role follows the same scope model as coder:

  • Project scope — can test coding across all sites or units within the assigned project.
  • Project-site scope — can test coding only at a specific site within a site-mode project.
  • Organization unit scope (org_unit) — can test coding within the assigned unit and its descendant subtree in an organization-mode project.

Access is granted through explicit role-scope assignments. The tester must be authenticated and active, and the target submission must fall within the tester’s assigned scope.

Workflow & Submission Behavior

When a coding_tester submits a coded VA form:

  1. The tester’s submission is saved and flagged as tester output (is_tester = True).
  2. It never becomes the case’s production result (it does not transition the case to coder_finalized).
  3. The VA form returns immediately to ready_for_coding so a production coder can be allocated the case.

Tester submissions do not open a 24-hour recode window and are excluded from coder, Data Manager, and burndown metrics.

Important Notes

Project PI and Site PI roles do not grant coding access. Users holding oversight roles must also have an explicit coder or coding_tester grant to enter the coding workflow.
Role scope: DigitVA uses a hybrid RBAC and ABAC model. Roles define capabilities (what you can do), and scopes define boundaries (where you can do it). Both must match for access to be granted.
