Overview

The grant management interface at /data-management/users lets you create users and manage coder, coding-tester, and data-manager grants within your own scope, without requiring admin intervention.

Access this page through the Manage Users button in the Data Manager Dashboard header.

This interface is separate from the admin panel at /admin/. Admins can also use this interface, but they already have the full admin panel available for broader role management.

Who Can Use This Interface

Role Access Level
data_manager Scoped by own grants — can only assign within own project/site scope
admin Full access, bypasses all scope restrictions

Assignable Roles

Through this interface, you may assign only these three roles:

  • coder — coding role within assigned scope
  • coding_tester — coding test role within assigned scope
  • data_manager — data-quality triage role within assigned scope
You cannot assign admin, project_pi, site_pi, reviewer, or collaborator roles through this interface. Those require admin panel access.

Scope Rules

The grants you can assign depend on your own grant scope:

Project-Scoped Data Manager

If you hold a project-level data-manager grant, you may assign grants at:

  • Project level — for the project where you hold your grant
  • Project-Site level — for any site within that project

Site-Scoped Data Manager

If you hold only project-site-level data-manager grants, you may assign grants at:

  • Project-Site level only — and only for the specific project-site pairs where you hold a grant
A site-scoped data manager may not assign project-level grants, even for the project that contains their assigned sites.

Admin

Admins bypass all scope restrictions and can assign grants at any project or site level.

Grant Scope Types

Scope Type Requirements Coverage
project Requires a project selection All sites within that project
project_site Requires both a project and a site selection Only the specified site within that project

Managing Grants

Viewing Grants

The Grants tab shows all coder, coding-tester, and data-manager grants within your scope. You can filter by user email to find a specific user's grants. Grants for other roles (admin, project PI, site PI, reviewer, collaborator) are never shown in this view, even if they exist within your scope.

Creating a Grant

  1. Go to the Grants tab
  2. In the new-grant form, select a user (or type an email to search)
  3. Select the project (must be within your manageable scope)
  4. Optionally select a site (required for site-scoped data managers; optional for project-scoped)
  5. Select the role: coder, coding_tester, or data_manager
  6. Submit the form
If an inactive grant with the same user, role, and scope already exists, the system reactivates it instead of creating a duplicate.

Activating / Deactivating Grants

Use the toggle action next to each grant to activate or deactivate it. You may toggle any grant that meets all of these conditions:

  • The grant role is coder, coding_tester, or data_manager
  • The grant falls within your scope
  • The grant is not your own data-manager grant
You cannot revoke your own data-manager grant through this interface. This prevents accidental lockout.

Creating Users

User Creation Form

From the Users tab, you can create new users. The form requires:

  • Email and Confirm Email (must match)
  • Name
  • Phone
  • VA Language (at least one must be selected)
  • Initial Grant — you must assign at least one grant during creation:
    • Project selection first (must be within your manageable scope)
    • Role: coder, coding_tester, or data_manager
    • Scope: project or project-site, depending on your own scope

New User Onboarding Flow

After you create a user, the following happens automatically:

  1. The user account is created with active status
  2. The user receives a verification email and a password-setup email
  3. The password-setup email uses invite wording ("set your password")
  4. When the user verifies their email for the first time, they are redirected to the password setup page
  5. After setting their password, the first login shows a terms-and-conditions gate
  6. The user's default landing page is set to the coder dashboard
You do not set a password for the user. The user sets their own password through the invite email flow.

User Details

From the Users tab, click on a user to open their details panel. This shows:

  • Account status (active / deactive)
  • Email verification status
  • User VA language list
  • In-scope active grant breakdown:
    • Project-level grants
    • Project-site-level grants
  • Resend verification action (for unverified users)
  • Email update action (only for users you created)
  • Language update action
  • Manage Grants shortcut — switches to the Grants tab with this user's email pre-filled in the search filter and the user preselected in the new-grant form

Scope Validation

Every grant creation and toggle action validates scope against your own grants. The system ensures that:

  • The target project is one where you hold a data-manager grant
  • The target site (if applicable) belongs to a project where you hold a project-level grant, or matches one of your project-site grants
  • Site-scoped data managers cannot assign at the project level

If you attempt to create or toggle a grant outside your scope, the request is rejected. All mutating endpoints require a valid CSRF token in the X-CSRFToken header.
