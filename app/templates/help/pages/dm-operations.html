Overview

As a data manager, your role is data-quality triage and operational review. You are not a coder and not a reviewer. You cannot start coding, submit COD assessments, or submit reviewer QA. Your actions focus on screening, diagnosing issues, and keeping the pipeline healthy.

The data manager role is separate from the coder role. Any action you take is recorded under your data-manager identity, never attributed to a coder.

Browsing Submissions

From the Data Manager Dashboard, you can browse all submissions within your grant scope. This is read-only access: you can open and inspect submission data, SmartVA results, ODK metadata, and attachment counts, but you cannot modify the submission payload.

Click the View action on a submission row to open the read-only detail page at /data-management/view/<va_sid>. This page includes a Data Triage panel with SmartVA summary details: outcome, result-for, age/gender, causes with ICD codes and likelihoods, key symptoms, and failure details when applicable.

Triggering Sync

Per-Form Sync

The sync modal on the dashboard lets you queue a full sync for a scoped form. To trigger a sync:

  1. Click the sync button in the dashboard header
  2. Select the project and site scope
  3. Confirm the matched forms and review the local vs ODK count preview
  4. Submit to queue the sync task through Celery
The sync modal reports that tasks have been queued, not that they are finished. Check the Recent Sync Results panel for completion status. Missing ODK records are flagged locally rather than deleted.

Single-Submission Refresh

A targeted refresh for one submission updates the local payload, attachments, SmartVA result, and local sync-issue status for the parent form. This action is available through the API and from the submission detail view.

Marking a Submission as Not Codeable

As a data manager, you can mark a submission as Not Codeable when it should not enter or continue through the coder workflow. This is a data-management triage decision, separate from a coder's Not Codeable outcome.

How It Works

  1. Open the submission detail page or use the triage action from the dashboard
  2. Select the Not Codeable action
  3. Provide a reason and optional notes documenting the decision
  4. Confirm the action

What Happens After

  • The decision is stored in va_data_manager_review as a data-manager-specific workflow record
  • An audit trail entry is created, clearly identifying the data manager as the actor
  • DigitVA attempts to write ODK Central review state hasIssues with a role-appropriate comment
  • The submission is excluded from all new coder allocation (normal and random/demo)
ODK Central write-back is a follow-up step, not a gate. If the ODK Central update fails, the local Not Codeable decision is preserved. You will see a warning that the local save succeeded but the ODK Central update failed. The failure is logged and discoverable in admin activity views.

Viewing Upstream Changes

When a previously finalized submission has been updated in ODK Central, it enters the finalized_upstream_changed state. The dashboard shows a View Changes action for these rows.

Change Categories

The View Changes modal presents three tabs:

Category Description
Data Changes Actual field value changes in the submission data
Metadata Changes Changes to submission metadata fields
Formatting-Only Changes Cosmetic differences with no semantic impact

Resolution Actions

After reviewing the changes, choose one of two resolution paths. Both actions require confirmation through a second modal before execution.

Action Effect
Accept And Recode Adopts the new ODK data, clears the old assigned ICD codes, and returns the submission to the smartva_pending state for a full recode path
Keep Current ICD Decision Adopts the latest ODK payload locally while preserving the current finalized ICD code decision and finalized workflow state
Upstream review actions from the View Changes modal are local DigitVA workflow resolutions. They do not write an ODK rejection comment back to ODK Central. This is distinct from the Not Codeable triage action, which does write ODK hasIssues review state.

Links to Reporting

From the dashboard and navigation, you have access to two reporting views:

  • KPI Dashboard — Key performance indicators for your scope, including coding throughput and quality metrics
  • COD Bucket Reporting — Cause-of-death distribution and bucket analysis for coded submissions in your scope

Both reports respect your grant scope and the current dashboard filter selection.
