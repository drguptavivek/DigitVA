ICD-10 Code Selection in DigitVA

During Step 2 of the coding workflow, coders select an ICD-10 cause of death code for the verbal autopsy submission. The ICD code selection system is built on the WHO ICD-10 2019 revision and enforces WHO VA 2022 coding allowability rules.

WHO ICD-10 Browser (Admin)

Administrators can browse and curate the ICD-10 hierarchy via the admin panel at /admin/panels/icd10-browser, backed by API routes under /admin/api/icd10/2019-2/*.

Key features:

  • Lazy hierarchy traversal — the browser loads one node and its direct children at a time, not the full tree in one response.
  • Policy-field curation — admins can edit local policy fields (is_coding_selectable, sex_selectable, age_group_selectable, restriction_note) on three-character and detailed-code rows. Chapters and blocks are structural only and cannot carry policy edits.
  • Status indicators — the browser uses color-coded indicators:
    • Green: the row or all direct children are selectable.
    • Yellow: the row itself is not selectable but has at least one selectable detailed child.
    • Red: neither the row nor any child is selectable.
  • JSON and XLSX export — admins and data managers can export curated code-policy rows for review or backup.

Local VA Codes (Reference Catalog)

DigitVA stores the ICD-10 2019 hierarchy as master reference data in mas_icd10_2019_2, loaded from the checked-in WHO ICD-10 2019 ClaML XML snapshot and generated hierarchy CSV. This catalog includes:

  • Chapters
  • Blocks
  • Three-character categories
  • Detailed dotted codes (including modifier-derived codes like V01.1, E10.0)

Coding-time lookup reads from this catalog and returns only selectable three_character and detailed_code rows. The legacy va_icd_codes table is deprecated and must not be used for new ICD lookup features.

ICD Code Restrictions

Not all ICD-10 codes are available during coding. Selectable codes are restricted based on WHO VA 2022 manual coding allowability rules:

  • Submission age classification determines which age-group codes are available:
    • neonate: 0 to fewer than 28 days
    • infant: 28 days to fewer than 365 days
    • child: 365 days to fewer than 12 years
    • adult: 12 years and older
  • Deceased gender restricts sex-specific codes:
    • Maternal O codes: female-only, adult-only
    • C51-C58: female-only
    • C60-C63: male-only
    • D25-D28: female-only
    • D29: male-only
    • C50: both sexes
  • Never selectable: codes in the range S00-T99 (injury codes) are never available for selection.
A code marked all for age group is available to every age classification. A code marked for a specific group (e.g., neonate) is available only to that group. The same applies to sex: both is universal; male or female restricts accordingly.

Coding Allowability Rules

The WHO 2022 VA crosswalk workbook defines the baseline set of allowed ICD codes. DigitVA generates a policy JSON from this crosswalk that controls which codes appear during coding. Key rules:

  1. Default allowed rows use is_coding_selectable=true, sex_selectable=both, and age_group_selectable=all.
  2. Exception rules override defaults for neonate-only, infant-only, and female-only conditions.
  3. Expansion preserves WHO granularity: three-character codes select only that code; dotted codes select only that exact dotted code.
  4. Overlap rules: never-selectable wins over all. Age and sex exceptions win over default allowability. The most restrictive applicable rule wins.

Validation on Submission

When a coder submits a final COD with an ICD-10 code, the system validates the selection against the coding allowability rules for that specific submission:

  • The code must be active and marked is_coding_selectable.
  • The code must be allowed for the submission’s age group.
  • The code must be allowed for the deceased’s gender.
Not all ICD-10 codes are available. Only codes relevant to verbal autopsy coding, as defined by the WHO 2022 instrument and local policy curation, can be selected. Codes for low-fatality or implausible conditions may be disabled through clinical review even when included in broad WHO residual ranges.

Policy Import and Export

ICD coding policy can be exported and re-imported:

  • Export: Includes all three-character and detailed-code rows where at least one policy field is set. Available in JSON and XLSX formats.
  • Import: Overwrite-style. Imported rows are updated from the file. All other editable ICD rows not present in the import are reset to is_coding_selectable=false and sex_selectable=NULL.
The import response includes counts of updated items, reset items, and any failed codes with reasons, so operators can verify the effect of a policy change.
