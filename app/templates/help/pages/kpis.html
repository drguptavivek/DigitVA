KPI Dashboard

The KPI Dashboard at /data-management/dashboard provides operational metrics for data managers to monitor the health of the coding pipeline. It is scoped to your data-manager grants: you see only the projects and sites you have been explicitly granted access to.

Scoping: Every KPI denominator is filtered through your grant scope. Project-level grants show all sites within that project. Project-site grants show only that specific pair. The dashboard never exposes data outside your authorized scope.

Data Sources

The dashboard uses a hybrid storage model:

  • Pre-computed daily grid — the va_daily_kpi_aggregates table stores one row per (snapshot_date, project_id, site_id) with daily counts of synced, coded, pending, refused, and not-codeable submissions, plus coding duration percentiles. This table is populated by a daily Celery task and refreshed after each sync run.
  • Event-sourced detail — detailed KPIs (reason breakdowns, language gaps, per-coder stats) are computed on-demand from va_submission_workflow_events and supporting tables.

Denominator Scopes

KPIs are computed against defined scopes that exclude or include certain workflow states:

Scope Definition
ALL-SYNCED Every submission in your scope, regardless of state
CONSENT-VALID ALL-SYNCED minus consent-refused submissions (hard gate)
CODING-POOL CONSENT-VALID minus DM-not-codeable submissions (soft gate)
CODED Submissions that reached coder_finalized or beyond
Hard vs. soft gates: Consent refusal is a hard gate (permanent exclusion). DM-not-codeable is a soft gate (reversible if ODK data is corrected). Both are tracked separately so data managers can act on soft-gated forms.

KPI Categories

Daily Operations

The primary view is a daily operations grid showing the last 8 days (today plus 7 prior days). Each row shows:

Column Description
Total Cumulative count of all synced submissions as of that day
New from ODK Submissions newly added from ODK sync runs on that day
Updated in ODK Submissions updated by ODK sync runs on that day
Coded Submissions reaching coder_finalized or recode_finalized on that day
Pending Coding Submissions in ready_for_coding, coding_in_progress, or coder_step1_saved states
Consent Refused Submissions transitioned to consent_refused on that day
Not Codeable Submissions marked not codeable (by coder or DM) on that day

Additional daily operation metrics include:

  • Sync status — status, start time, and finish time of the most recent ODK sync run
  • Sync error rate — percentage of sync runs that resulted in error or partial status over 7-day and cumulative windows
  • % Uncoded — fraction of the coding pool that has not yet been coded
  • % Not Codeable — fraction of all synced submissions that are in a not-codeable state
  • Consent refusal rate — fraction of all synced submissions where consent was refused
  • Pipeline aging — count of submissions stuck in ready_for_coding beyond 48 hours, 7 days, and 30 days

Timing Metrics

  • Time to Code — for each finalized submission, the elapsed time from coding_started to coder_finalized. Reported as minimum, maximum, median (P50), and P90 percentile. Covers both first-pass coding and recode episodes.
  • Sync latency — time between the ODK submission timestamp and the local database insert. Reported as P50, P90, and P99.
  • Predicted days to clear backlog — estimated days to code all currently pending forms, computed as pending_count divided by the mean daily coding rate over the trailing 7 days. Also reported per language.

Coder Metrics

  • Coder throughput — count of coder_finalized events in the selected window, with per-coder breakdown
  • Coder utilization rate — percentage of active coders who have at least one active allocation. Low utilization (<70%) suggests idle coders; high utilization (>95%) suggests saturation.
  • Coder output by language — a heatmap showing how many forms each coder has produced in each language, with per-language backlog totals
  • Coder pool — list of active coders, their assigned languages, total forms coded, and currently allocated count

Quality Metrics

  • % Forms reviewed — fraction of coded submissions that have at least one active reviewer final assessment. Excludes coder_finalized forms less than 24 hours old (the recode window).
  • Upstream change queue — count of submissions currently in the finalized_upstream_changed state, indicating ODK data changed after coding
  • Upstream change resolution time — median time to resolve upstream changes over the trailing 7 days
  • Coder-reviewer disagreement rate — among submissions with both coder and reviewer final assessments, the percentage where the conclusive COD differs
  • NQA completion rate — percentage of coded submissions (in projects where Narrative Quality Assessment is enabled) that have an active NQA record
  • Social Autopsy completion rate — percentage of coded submissions (in projects where Social Autopsy is enabled) that have an active Social Autopsy record

Backlog Metrics

  • Coding backlog trend — daily time-series of the count of submissions in ready_for_coding, shown as a line chart over a configurable window (default 90 days)
  • Burndown chart — compares the projected completion trajectory against actual cumulative coding progress. Requires an admin-configured target completion date for the project.
  • Daily inflow vs outflow — side-by-side bar chart comparing new forms entering the coding pipeline against forms coded each day. Consistent positive net delta means the backlog is growing.
  • Reopen rate — fraction of finalized forms that were re-opened for recoding (via upstream change acceptance or admin override)

Infrastructure Metrics

  • Attachment health — percentage of submissions past the SmartVA gate that have zero attachments. A high rate indicates attachment sync problems.
  • Attachment completeness — ratio of successfully downloaded attachments to total attachment attempts in the latest sync run
  • SmartVA failure rate — percentage of SmartVA runs that failed over 7-day and cumulative windows

Language Metrics

  • Language gap alert — count of submissions in ready_for_coding where the narration language has zero active coders who know that language. Includes a breakdown of which languages are affected and how many submissions are blocked.
  • Language bottleneck — table ranking languages by pendency (pending count descending), showing available coders and predicted days to clear for each language
  • Language-not-codeable correlation — percentage of language-related not-codeable decisions that correspond to languages in the gap set
  • Missing/unmapped language forms — count of submissions in the coding pool where the narration language is blank, null, or not present in the language alias mapping table. These forms cannot be language-matched to coders.

API Endpoints

The dashboard loads all data asynchronously via JSON API endpoints under /api/v1/analytics/dm-kpi/. No full-page reloads are needed for filter changes. Key endpoints include:

Endpoint Returns
GET /api/v1/analytics/dm-kpi/grid/ Daily operations grid rows from pre-computed aggregates
GET /api/v1/analytics/dm-kpi/scope/ KPI card counts and summary metrics
GET /api/v1/analytics/dm-kpi/language/gap Language gap analysis and bottleneck data
GET /api/v1/analytics/dm-kpi/exclusions/rates Not-codeable reason breakdowns by actor
GET /api/v1/analytics/dm-kpi/exclusions/blocked Blocked forms alert data
GET /api/v1/analytics/dm-kpi/coders/utilization Coder utilization statistics
GET /api/v1/analytics/dm-kpi/coders/output Coder output breakdown by language
GET /api/v1/analytics/dm-kpi/burndown/ Predicted vs achieved time-series for burndown chart
GET /api/v1/analytics/dm-kpi/pipeline/ Pipeline aging and workflow state distribution
GET /api/v1/analytics/dm-kpi/workflow/ Workflow transitions and state velocity
GET /api/v1/data-management/kpi Legacy KPI card counts (DM dashboard)
GET /api/v1/data-management/filter-options Available filter values (projects, sites, languages, states)
GET /api/v1/data-management/submissions Paginated submission table (infinite scroll)

All endpoints accept query parameters for filtering (project, site, lang, range, state). Filter state is stored in the URL query string so dashboard views can be bookmarked and shared.

Blocked Forms Alert

The dashboard identifies submissions in the coding pool that cannot be routed to a coder right now, grouped by blockage reason:

Blockage Reason Action Required
Awaiting DM screening Pass or reject screening
Attachments not synced Trigger attachment sync
Missing attachments Re-trigger attachment sync; check ODK Central
SmartVA not run Check SmartVA queue
Upstream change pending Accept or reject the upstream change
Missing or unmapped language Fix language mapping or add alias
Language gap (no coders) Recruit or reassign coders
ODK flagged (hasIssues) Coordinate with field team
This alert list is the data manager's action queue. Working through blocked forms directly increases pipeline throughput.
