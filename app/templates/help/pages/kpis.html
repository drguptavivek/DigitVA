KPI Dashboard

The KPI Dashboard at /data-management/dashboard provides operational metrics for data managers to monitor the health of the coding pipeline. It is scoped to your data-manager grants: you see only the projects and sites you have been explicitly granted access to.

Scoping: Every KPI denominator is filtered through your grant scope. Project-level grants show all sites within that project. Project-site grants show only that specific pair. The dashboard never exposes data outside your authorized scope.

Core Panels and Registered KPIs

The dashboard keeps a small set of 18 core panels: the numbers that matter most, always in the same place. A further 35 registered KPIs have no fixed panel but can be looked up by name or id. Every KPI is classified by where it sits in the results chain:

Stage What it answers Examples
Input What do we have to work with? Coder availability, language gap
Process How do cases move? Uncoded and when it will clear, blockers, time in each state, ODK sync
Output What did we produce? Cases coded each day, final cause coverage, cases lost to coding, interviews that cannot be analysed
Outcome What do the results say? Share of finals with no meaningful cause, coder-reviewer agreement, female against male coverage

Within a stage, KPIs are grouped by category, such as workforce, flow, timeliness, coding quality, coverage, data quality and equity. Some earlier KPIs are now a breakdown of another one (for example, not-codeable by coder or by data manager is a breakdown of “cases lost to coding”); their ids still work.

Small numbers: A count under 5 is folded, and a rate or rank is shown only when it rests on 20 or more cases. Comparisons are only with sibling units inside your own grant (districts with districts, PHCs with PHCs). Coverage of reported deaths and the register part of the female-male comparison apply only to projects that keep a death register.

Blockers, Critical Path, Forecast and Trend

  • Blockers — for each reason a case is stuck: how many, how old (median and oldest) and who can unblock them.
  • Critical path — the typical and slow (90th percentile) time cases spend in each stage. The dominant stage takes the largest share of the total time. The bottleneck is the stage where you are furthest behind your sibling units (shown when there are 20 or more cases).
  • Forecast — days to clear is the pending count divided by the average daily outflow of the last 28 days, with a range from the lowest and highest of the last four weekly rates. A capacity ceiling (coders times their recent rate) is shown as an assumption, not blended into the estimate. If more cases arrive than leave over 28 days, the forecast says it does not clear. Each forecast is checked against what happened over the past 12 weeks. No forecast is shown for fewer than 20 cases.
  • Trend — the change from the previous period and, once 13 months of history exist, from the same period last year. A KPI is flagged rising or falling when the last four weeks differ from the four before by at least 10% and at least 5 cases; otherwise it is flat.

For AI Agents

Data managers and admins can create a personal access token (after signing in again) and let an AI assistant query KPI aggregates. The token works only on the KPI endpoint, lasts at most 90 days, can be revoked, and sees only what your own grants allow. Results are aggregates: counts under 5 show as <5, rates on fewer than 20 cases are left out, and no names are returned.

Data Sources

Every number on the dashboard is worked out live from the record of what happened to each case (its workflow events), so it is always current. Nothing is stored in a nightly snapshot.

  • Days follow your timezone — “today” and each row of the daily grid start at midnight in your own timezone (India time unless you have set another).
  • Demo sessions are left out — practice (demo) coding is not counted in coded, throughput, rate or time-to-code figures. Demo projects still appear in your scope.
  • Pending means not yet coded — every case still being screened, waiting for attachments or SmartVA, ready for coding, or part-way through coding. The “ready pool” is the smaller set of cases a coder can pick up right now.

Denominator Scopes

KPIs are computed against defined scopes that exclude or include certain workflow states:

Scope Definition
ALL-SYNCED Every submission in your scope, regardless of state
CONSENT-VALID ALL-SYNCED minus consent-refused submissions (hard gate)
CODING-POOL CONSENT-VALID minus DM-not-codeable submissions (soft gate)
CODED Submissions that reached coder_finalized or beyond
Hard vs. soft gates: Consent refusal is a hard gate (permanent exclusion). DM-not-codeable is a soft gate (reversible if ODK data is corrected). Both are tracked separately so data managers can act on soft-gated forms.

KPI Categories

Daily Operations

The primary view is a daily operations grid showing the last 8 days (today plus 7 prior days). Each row shows:

Column Description
Total Cumulative count of all synced submissions as of that day
New from ODK Submissions newly added from ODK sync runs on that day
Updated in ODK Submissions updated by ODK sync runs on that day
Coded Submissions reaching coder_finalized or recode_finalized on that day
Pending Coding Cases not yet coded at the end of that day: being screened, waiting for attachments or SmartVA, ready for coding, or part-way through coding
Not analysable Interviews that cannot be analysed (refused, respondent unavailable, partially completed; ODK consent = no counts as refused) transitioned to consent_refused on that day
Not Codeable Submissions marked not codeable (by coder or DM) on that day

API Endpoints

The dashboard loads all data asynchronously via JSON API endpoints under /api/v1/analytics/dm-kpi/. No full-page reloads are needed for filter changes. Key endpoints include:

Endpoint Returns
GET /api/v1/analytics/dm-kpi/grid/ Daily operations grid rows, computed live
GET /api/v1/analytics/dm-kpi/scope/ KPI card counts and summary metrics
GET /api/v1/analytics/dm-kpi/language/gap Language gap analysis and bottleneck data
GET /api/v1/analytics/dm-kpi/exclusions/rates Not-codeable reason breakdowns by actor
GET /api/v1/analytics/dm-kpi/exclusions/blocked Blocked forms alert data
GET /api/v1/analytics/dm-kpi/coders/utilization Coder utilization statistics
GET /api/v1/analytics/dm-kpi/coders/output Coder output breakdown by language
GET /api/v1/analytics/dm-kpi/burndown/ Predicted vs achieved time-series for burndown chart
GET /api/v1/analytics/dm-kpi/pipeline/ Pipeline aging and workflow state distribution
GET /api/v1/analytics/dm-kpi/workflow/ Workflow transitions and state velocity
GET /api/v1/data-management/kpi Legacy KPI card counts (DM dashboard)
GET /api/v1/data-management/filter-options Available filter values (projects, sites, languages, states)
GET /api/v1/data-management/submissions Paginated submission table (infinite scroll)

All endpoints accept query parameters for filtering (project, site, lang, range, state). Filter state is stored in the URL query string so dashboard views can be bookmarked and shared.

Blocked Forms Alert

The dashboard identifies submissions in the coding pool that cannot be routed to a coder right now, grouped by blockage reason:

Blockage Reason Action Required
Awaiting DM screening Pass or reject screening
Attachments not synced Trigger attachment sync
Missing attachments Re-trigger attachment sync; check ODK Central
SmartVA not run Check SmartVA queue
Upstream change pending Accept or reject the upstream change
Sent back for revision Wait for the interviewer, or cancel the request
Missing or unmapped language Fix language mapping or add alias
Language gap (no coders) Recruit or reassign coders
ODK flagged (hasIssues) Coordinate with field team
This alert list is the data manager's action queue. Working through blocked forms directly increases pipeline throughput.
