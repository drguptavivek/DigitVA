Sites

The Sites panel at /admin/panels/sites lets administrators manage site master data. Sites represent physical data-collection locations (such as hospitals or research centers) and are a core organizational unit in DigitVA's access control and data-partitioning model.

Creating a Site

To create a new site, click New Site and provide:

Field Description
Site Identifier A short, unique code for the site (for example, "NC01", "KA01"). This identifier is used throughout the system in form IDs, allocation, and reporting.
Site Name A human-readable name for the site.
Active Status Whether the site is currently active. Inactive sites do not participate in sync or coding allocation.

Site Identifiers

Site identifiers are embedded in several derived values across the application:

  • Form IDs combine the project code and site identifier (for example, "UNSW01KA0101").
  • Submission identifiers include the form ID, which carries the site.
  • Access grants can be scoped to a specific project-site combination using the site identifier.
Choose stable, short site identifiers at creation time. The identifier becomes part of stored form IDs and submission references that are difficult to rename later without data migration.

How Sites Relate to Projects and Forms

Sites do not belong to a single project. Instead, sites are mapped to projects through the Project-Site association panel:

  • A site can be associated with multiple projects.
  • Each project-site combination can have at most one ODK form mapping configured through the Project Forms panel.
  • When a project-site mapping is active and has an ODK form linked, the sync pipeline downloads submissions for that combination.

The relationship chain is:

  1. Site — the physical location (managed here).
  2. Project-Site — links a site to a project (see Project-Site Associations).
  3. Project-Form — links an ODK form to a project-site pair (see Project-Form Settings).

Site Maintenance Mode

The admin sync dashboard includes a global Site Maintenance control that activates a maintenance mode with a fixed 15-minute grace window followed by enforced shutdown.

Grace Period (First 15 Minutes)

  • A bottom-centered maintenance banner appears for all authenticated users.
  • Non-admin users see a countdown timer showing time remaining before cutoff.
  • During the grace period, non-admin users may continue working normally.
  • An optional admin-supplied message can be displayed to explain the reason for maintenance.

After Cutoff

  • Non-admin users are automatically logged out.
  • Non-admin login is blocked.
  • Admin users can still log in and access the full admin panel.
  • The banner and countdown are pushed into already-open pages through a shared status poller, so users do not need to manually refresh.
The grace window is fixed at 15 minutes. Plan maintenance activities within this window. After cutoff, all non-admin sessions are terminated. Admin users remain fully operational throughout.

Editing and Deactivating Sites

Existing sites can be edited to update their name or other attributes. Deactivating a site:

  • Removes the site's forms from the sync pipeline.
  • Excludes the site's submissions from coder allocation.
  • Does not delete the site's data, submissions, or historical coding artifacts.
If a site is moved between projects and the old project-site row is deactivated, old forms from that deactivated pair are excluded from coder access and random allocation. Ensure that project-site associations are updated before deactivating old mappings.
