What Is the Coding History Table?

The coding history table on the coder dashboard shows all submissions that the current coder has previously coded or finalized. It provides a record of past work and access to view, and in some cases recode, completed submissions.

Table Columns

The history table displays the following information for each submission:

Column Description
Project Code The project associated with the submission.
Site Code The site where the verbal autopsy was conducted.
VA Form ID A masked identifier for the verbal autopsy submission.
Age / Gender Combined column showing the deceased's age and gender, used in ICD-10 code filtering.
VA Code Status Display label for the current state: "In Progress", "VA Coding Completed", or "Not Codeable".
VA Coding Date Date and time when the coder finalized the COD, displayed in the user’s timezone.
Actions Continue (for in-progress), View (read-only), or Recode (during 24-hour window) buttons.

View Button

Each row in the history table has a View button that opens the submission in read-only mode. This allows the coder to review their previous coding work, including:

  • All submission categories and narrative data
  • Narrative Quality Assessment (if applicable)
  • Social Autopsy Analysis (if applicable)
  • Step 1 initial COD assessment
  • Final COD with ICD-10 code

Recode Button

Submissions that are still within the 24-hour recode window display a Recode button. Clicking it reopens the submission for the coder to change their COD determination.

  • The recode button is available only while the submission is in coder_finalized state and within 24 hours of finalization.
  • Once the submission transitions to reviewer_eligible (after the 24-hour window), the recode button is no longer shown.
  • The existing finalized COD remains authoritative until a replacement final COD is successfully saved.
Supporting artifacts persist during recode. NQA and Social Autopsy artifacts are preserved when reopening a case for recode, unlike first-pass coding where they are deactivated on timeout.

Workflow State Transitions

The workflow state column reflects the current position of each submission in the state machine. Common states visible in the history table:

State Meaning
coder_finalized Final COD submitted. Recode button may be available if within 24 hours.
reviewer_eligible Recode window has closed. Waiting for optional reviewer coding.
reviewer_coding_in_progress A reviewer is currently coding the submission.
reviewer_finalized A reviewer has submitted a reviewer final COD.
finalized_upstream_changed ODK data changed after finalization. Pending resolution by data manager or admin.
not_codeable_by_coder The coder marked the submission as not codeable.

Workflow History

Each submission maintains a detailed workflow event history that records all state transitions and their timestamps. This includes:

  • When coding was started
  • When Social Autopsy analysis was saved
  • When Narrative Quality Assessment was saved
  • When Step 1 COD was submitted
  • When final COD was submitted
  • When the recode window expired
  • When reviewer became eligible
  • When reviewer coding started and finalized
  • When stale allocations were released

Admin Activity Log

Administrators have access to an additional activity log panel that provides an audit trail of all workflow actions across all submissions. This log is sourced from va_submissions_auditlog and is visible only to users with the admin role.

The admin activity log records milestone events for each submission, making it possible to reconstruct the full coding timeline including who performed each action and when.

Output Metrics

The coder dashboard also displays authored-output metrics separately from the history table:

  • Cumulative Forms Coded — counts active coder-authored final assessments on non-demo projects. This count includes cases that have advanced to reviewer_eligible.
  • Marked Not Codeable — counts active coder-authored Not Codeable reviews.
Demo-training project coding does not contribute to these output metrics.
